# NetworkDiagramStudio 0.1.0-preview.9

- Import Base64 SonicWall EXP settings directly, including TZ 600, TZ 670 and NSA 3600 identities, interface addressing, VLAN parents and supported route fields. Only normalized topology fields are retained. Opaque or encrypted backups remain unsupported.
- Expand prefixed interface ranges in CX, classic Aruba stacks, chassis modules and Cisco interface blocks. Preserve the individual ports, descriptions, native/tagged VLANs and classic Trk memberships. Unsupported cross-member or oversized ranges produce review notices instead of fictional range-named interfaces.
- Map FortiGate 90G/91G revision 2 x1/x2 interfaces to their documented shared port bays, separately from revision 1 wan1/wan2 names. Explicit copper or fiber settings select the corresponding shared jack. A shared-media capability alone does not establish copper, fitted optics or negotiated speed.
- Add the TZ600 rear connector panel. Paired native sockets retain opposite orientations. Combo RJ45/SFP access sockets remain attached, and declared stack members expose unused physical jacks as endpoint choices.
- Stack leads use separate inter-panel lanes in core drawings and exterior rails on wireless sheets, keeping cables clear of other members. Core packing allocates more space to stacks.
- Device details includes editable stack-member and installed-module rows. Confirm 2920 A/B rear modules as J9731A or J9732A. Their rear connectors stay separate from the front panel; an unspecified module retains its boundary behavior. Chassis card and member assignments persist and participate in project history.
- Add further 3560-E 48-port model aliases and confirmed X2/TwinGig uplink slots. A Te0/1 uplink can no longer attach to RJ45 access port 1. Select the installed X2 transceiver or CVR-X2-SFP card before using exact uplink socket positions.

The uploaded configurations were checked privately. Their raw contents, customer names and credentials are absent from repository fixtures and screenshots. Files without an exact model declaration still need a confirmed Model selection or mapped stencil. The supplied binary RouterOS-style backup requires a RouterOS text export; it is not converted into invented devices or ports.

Validation passes 80 Node tests, three damaged-package rejection tests, four complete synthetic Visio packages and the hardware drawing downloaded through the browser. It covers range/member/module imports, bounded EXP decoding, shared-media and revision handling, connector orientation, aliases, physical port filtering, stack route geometry and native export. Browser checks cover the hardware editor, history and save/reopen plus existing color, snapping, selection, cable and port-mapper tools. Hosted Windows lifecycle and publication checks are required before release. Direct opening in Microsoft Visio remains unverified in this environment.
