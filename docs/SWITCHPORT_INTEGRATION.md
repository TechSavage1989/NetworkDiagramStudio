# Switchport Diagram Builder integration

## Audited baselines

The source audit follows actual handlers, parser branches, normalized types, layout solvers and file writers in [SwitchPort_Diagram_Builder commit 2327083bcd4301db1cc7c162a764540190c5d7ad](https://github.com/TechSavage1989/SwitchPort_Diagram_Builder/tree/2327083bcd4301db1cc7c162a764540190c5d7ad), version 1.18.5. The NetworkDiagramStudio comparison baseline is preview.31, commit 2a49a7b03e2a76e1ebab2309a6815546e1007c44. The baseline column records what was absent before this integration; it is not the current completion status. Current implementation, verification and the remaining platform publication gate are recorded below.

The upstream generated catalog contains 453 records: 235 supported switches, 44 supported chassis/bundle identities, 2 supported firewalls, 75 supported modules and 97 research-pending products. Its InstantOnParser additionally accepts ten verified 1930 SKUs absent from DeviceModels.Choices and the generated CSV. Integration retains those ten profiles. Research-pending entries remain unconfirmed and are not made drawable by a generic count.

Evidence paths below are relative to the upstream Source directory unless prefixed NDS. The complete reusable source is retained in NDS desktop/SwitchportReports/Engine, with exact source provenance in desktop/SwitchportReports/UPSTREAM.md. This avoids a second application interface or update feed.

## Status meanings

- Existing: the preview.31 editor already provides the behavior through its normal workflow. Regression verification still applies.
- Partial: preview.31 supplies some behavior or metadata, but not complete Switchport behavior.
- Missing: the behavior was absent at preview.31.
- Native: the reusable native engine/facade implements the upstream capability inside the existing desktop host.
- Integrated: the common report/editor workflow exposes the capability. Verification cases in the inventory remain useful regression requirements; completed automated and real-browser checks are listed at the end.
- Host equivalent: use the existing NetworkDiagramStudio host behavior where it serves the same purpose. Keep its application identity, feed and lifecycle.

## Native API and browser data boundary

NetworkDiagramStudio.SwitchportReports.SwitchportReportService exposes CatalogJson, ImportJson, SupplementaryJson, PreviewJson and ExportJson. Request JSON uses camel-case properties and accepts ordered items containing an upstream Inventory, a normalized NDS device, or both. Device report metadata is read from reportDetails and switchportInventory. Direct stackMembers/modules are authoritative; the nested hardwareComposition spelling remains a compatibility fallback. A browser-decoded routerosSnapshot is accepted as normalized input. Raw configuration decoding is limited to ImportJson, with no raw persistence or export.

The request carries outputLabel, optional title, combined, optional logoDataUrl and palette. Preview returns plain boxes, labels, circles/diamonds, polygons with explicit x/y pairs, images, page roles, source device IDs and per-item status. This allows SVG and native Visio adapters to preserve actual report geometry instead of embedding report screenshots. Export returns the package directory, exact produced paths, per-item results, warnings and copyable summary text.

The reusable C# library is .NET 8. Its only graphics dependency is pinned SkiaSharp 3.119.4 with matching native assets. Embedded resource names remain SwitchportGenerator.Fonts and SwitchportGenerator.Data for the upstream loaders. The existing desktop host excludes nested library sources from its own compile items and references the library project. The final Windows package remains one portable EXE with its matching native renderer included in extraction. DejaVu and SkiaSharp notices accompany that existing host.

The offline browser data is generated from the same native catalog using the test executable's --catalog mode. Its moduleSlots reference moduleLayouts fragments that retain exact group, port, member, slot, suffix and interface aliases. Empty/default configuration state is omitted from the generated module and restored as unknown by its consumer. Verified socket geometry is never reconstructed from the largest observed port number.

## Unreleased parity refresh: upstream 1.18.6

Compared current upstream commit 349236a8cd04cb9def8053fb2cbce9610fc3dc07 with the pinned 1.18.5 engine. This is a targeted reconciliation, not a claim that the browser implements every native vendor command.
